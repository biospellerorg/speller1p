# Внешняя программа P300-LLM (p300_app)

Модуль подключает к спеллеру программу P300-LLM (`p300_app-dev_cpu_sync`). Программа работает как есть, без изменений: она показывает экран испытуемого, читает усилитель и сама декодирует ЭЭГ. Модуль ничего не рисует, он только передаёт спеллеру её вспышки и решения.

## Как это работает

Каждое событие P300-LLM сразу дописывается в `data/session_*/events.jsonl`. Модуль следит за самой новой папкой сессии и переводит события в контракт `speller-link@2`.

| Событие P300-LLM | Что получает спеллер |
|---|---|
| `config/defaults.json`, `config_snapshot.json` сессии | клавиатура 5×10: `ПРОБЕЛ` → `_`, `УДАЛИТЬ` → `⌫`; кнопка «ЗАВЕРШИТЬ» не входит |
| `target_started` | начинается очередная эпоха спеллера |
| `stimulus_started` (строка или столбец) | `flash` с меткой времени `lsl_timestamp`, снятой в P300-LLM сразу после flip |
| `decoding_prediction` | оценка ЭЭГ по трём лучшим символам её декодера (`top3_weights`), затем `done` |
| прерывание, ошибка, нет решения за `decision_wait_s` | `usable=false`: спеллер не выбирает символ и повторяет эпоху |

История не проигрывается: журнал, который уже есть при запуске модуля, читается только с конца, а новые папки сессий — с начала. Одних меток времени для этого мало, потому что часы LSL после перезагрузки компьютера начинают отсчёт заново.

## Ограничения

- **Обратной связи нет.** P300-LLM не знает о спеллере. Она набирает свой заданный текст, показывает цель перед каждой буквой, делает все повторения и показывает свою догадку. Досрочной остановки нет.
- **Оценка грубая.** В журнале P300-LLM есть только три лучших символа её декодера, без баллов. Поэтому символ на 1-м месте получает вес 8, на 2-м — 3, на 3-м — 2, остальные — 1. При таком весе языковая модель может перевесить декодер. Веса задаются в `settings.json`.
- **Один компьютер.** Модуль читает файлы P300-LLM, а метки времени в часах LSL этой машины.
- **Только «мигания».** Для «движений» у P300-LLM нет декодера.

## Запуск

1. В `settings.json` этого модуля укажите `p300_app_dir` — папку P300-LLM, где лежат `run.bat` и `config\defaults.json`. Обратные слэши в JSON удваиваются: `"C:\\bci\\p300_app-dev_cpu_sync"`.
2. Запустите спеллер: `uv run --no-sync python -m eeg_speller.external.server`. Откройте http://127.0.0.1:8770/.
3. В окне оператора:
   - задание: та же фраза, что в P300-LLM;
   - физиология: «Внешняя программа: P300-LLM (p300_app)»;
   - нажмите «начать сессию».
4. Запустите P300-LLM (`run.bat`) и выберите:
   - «ИНФЕРЕНС»;
   - ЭЭГ, «мигания»;
   - модель `xlda` или `eegnet`;
   - вход LSL от усилителя;
   - боковую панель декодирования лучше выключить, чтобы испытуемый не видел догадку P300-LLM.

В журнале модуля (под кнопками окна оператора) видно, какая буква P300-LLM попала в какую эпоху спеллера.

**Пауза между буквами.** Спеллер начинает эпоху сразу и ждёт вспышки до `external.epoch_timeout_s` (по умолчанию 120 с). Если между буквами P300-LLM бывают паузы дольше, увеличьте `epoch_timeout_s` в `configs/ext_default.yaml`. Иначе простоявшая эпоха закончится по таймауту и будет записана как попытка без выбора.

## Проверка

`tests/test_p300_app_bridge.py`:
- клавиатура из конфига P300-LLM;
- метки вспышек передаются без изменений;
- кнопка «ЗАВЕРШИТЬ» не передаётся;
- старые события пропускаются, в том числе журнал с метками из-за перезагрузки;
- при прерывании и без решения уходит `usable=false`;
- модуль переходит на новую папку сессии и дочитывает незаконченные строки;
- сквозной прогон через настоящий спеллер по LSL: имитатор пишет журнал так же, как P300-LLM, спеллер набирает «да», все 20 меток вспышек приходят с расхождением меньше 1 мс.
